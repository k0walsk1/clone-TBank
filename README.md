
# Fintech Dashboard — учебный банковский веб-сервис (клон ТБанка)

**Fintech Dashboard** — учебный frontend-проект, представляющий собой интерактивный веб-сервис для управления личными финансами. Визуально и функционально проект вдохновлён современными банковскими приложениями.

Основная цель проекта — практическое изучение JavaScript на примере разработки приложения с реальными пользовательскими сценариями: управлением счетами, переводами, накоплениями, историей операций, аналитикой расходов и виртуальным инвестиционным портфелем.

Отдельное направление проекта — изучение автоматизированного тестирования JavaScript-приложений: написание Unit-тестов, интеграционное и End-to-End тестирование, проверка асинхронных операций и автоматизация запуска тестов.

Проект создаётся в рамках самостоятельного обучения frontend-разработке с акцентом на асинхронное программирование, работу с REST API, обработку и преобразование данных, динамическое обновление интерфейса, клиентскую бизнес-логику и обеспечение качества кода.

> **Важно:** проект является учебной симуляцией банковского приложения. Все счета, балансы, переводы и инвестиционные операции виртуальные. Реальные денежные транзакции и банковские операции не выполняются.

## 🧪 Автоматизированное тестирование

Автоматизированное тестирование является отдельным направлением обучения в рамках проекта. Тесты разрабатываются параллельно с реализацией функциональности, чтобы проверять корректность бизнес-логики, взаимодействие модулей и пользовательские сценарии.

### 1. Unit Testing — модульное тестирование

Используется **Vitest** для проверки отдельных функций и небольших независимых модулей.

Планируемые сценарии:

- Проверка расчёта баланса после перевода.
- Проверка достаточности средств.
- Валидация суммы перевода.
- Расчёт комиссий.
- Форматирование денежных значений.
- Фильтрация и сортировка операций.
- Расчёт доходов и расходов.
- Расчёт инвестиционной прибыли и убытков.

*Изучаемые темы:* `describe`, `it`, `test`, `expect`, assertions, test cases, positive и negative testing.

### 2. Integration Testing — интеграционное тестирование

Проверка взаимодействия нескольких модулей и корректности обмена данными между ними.

Планируемые сценарии:

- Взаимодействие модулей счетов и переводов.
- Создание операции после успешного перевода.
- Обновление балансов после изменения данных.
- Получение и обработка данных из JSON Server.
- Проверка взаимодействия API-модуля с бизнес-логикой.
- Проверка обработки ошибок и некорректных ответов сервера.

*Изучаемые темы:* тестирование взаимодействия модулей, асинхронные тесты, mocks, stubs, подмена API-ответов, изоляция тестовой среды.

### 3. End-to-End Testing — сквозное тестирование

Используется **Playwright** для автоматизации действий пользователя в браузере и проверки приложения целиком.

Планируемые сценарии:

- Регистрация и авторизация пользователя.
- Создание нового счёта.
- Перевод средств между счетами.
- Проверка изменения балансов.
- Просмотр истории операций.
- Поиск, фильтрация и сортировка данных.
- Создание и пополнение финансовой цели.
- Проверка отображения аналитики.

*Изучаемые темы:* browser automation, locators, assertions, пользовательские сценарии, проверка интерфейса и взаимодействие с браузером.

### 4. DOM Testing — тестирование интерфейса

Используется **Testing Library** совместно с jsdom для проверки поведения DOM и взаимодействия пользователя с элементами интерфейса.

Планируемые сценарии:

- Проверка отображения элементов после загрузки данных.
- Проверка отправки и валидации форм.
- Проверка сообщений об ошибках.
- Проверка отображения пустых состояний.
- Проверка обновления интерфейса после действий пользователя.

*Изучаемые темы:* DOM queries, user events, assertions, тестирование доступности и поведения интерфейса.

### 5. CI — непрерывная интеграция

Используется **GitHub Actions** для автоматического запуска тестов при отправке изменений в репозиторий и создании Pull Request.

Планируемые задачи:

- Настройка workflow.
- Автоматическая установка зависимостей.
- Запуск Unit- и Integration-тестов.
- Запуск E2E-тестов.
- Проверка результатов выполнения тестов.
- Получение информации об ошибках непосредственно в GitHub.

*Изучаемые темы:* CI, workflow, автоматизация проверок, GitHub Actions, тестирование перед слиянием изменений.

## 🗂 Работа с данными и API

Для имитации серверной части используется **JSON Server**.

Тестовые данные хранятся в JSON-файле, а взаимодействие с ними осуществляется через REST API.

Предполагаемые сущности приложения:

| Сущность        | Описание                            |
| --------------- | ----------------------------------- |
| `users`         | Пользовательские профили            |
| `accounts`      | Банковские счета и балансы          |
| `transactions`  | История финансовых операций         |
| `goals`         | Накопительные цели                  |
| `expenses`      | Категории и данные расходов         |
| `investments`   | Виртуальный инвестиционный портфель |
| `notifications` | Пользовательские уведомления        |
| `settings`      | Настройки приложения                |

Для получения биржевых данных планируется использовать внешнее API. Рыночные котировки будут отделены от локальных тестовых данных.

**Принцип взаимодействия:**

`HTML/CSS/JavaScript → Fetch API → JSON Server → JSON`

Для инвестиционных данных:

`JavaScript → Fetch API → External Market API`

JSON Server используется исключительно в учебных целях и не является полноценной защищённой серверной инфраструктурой.

## 🚀 Запуск проекта

1. Клонировать репозиторий:

```
git clone <repository-url>
```

2. Перейти в директорию проекта:

```
cd fintech-dashboard
```

3. Установить зависимости:

```
npm install
```

4. Запустить JSON Server:

```
npx json-server database/db.json --port 3000
```

5. Открыть `index.html` через локальный сервер, например Live Server в VS Code.

Команды запуска тестов будут добавлены в `package.json` после настройки Vitest и Playwright.

## 💡 Результат обучения

В результате разработки проекта планируется получить практический опыт создания интерактивного клиентского приложения, способного работать с тестовой базой данных и внешними API.

Проект направлен на закрепление фундаментальных навыков JavaScript, понимание взаимодействия frontend-приложения с серверной частью и освоение принципов автоматизированного тестирования.

**Главный акцент — не на создании настоящего банковского продукта, а на реализации сложной клиентской логики, асинхронной работе с данными, построении функционального пользовательского интерфейса и обеспечении качества кода с помощью автоматизированных тестов.**
